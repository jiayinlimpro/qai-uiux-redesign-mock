# Screens · Results

## 6.1 Run results + result detail
**Header bar** Title "Run #12 · 83 tests"; below it the run facts, each with its icon: scope · environment · browsers (D85) · date · cost (+ "Stopped at x/y", D55); "Runs › Run #12" is the top bar breadcrumb (D31, as in 5.2). **Summary tiles** (D80; toggles, act as the status filter): All 83 · Failed 8 · Couldn't complete 3 · Passed 72 (· Not run n if any), one row, each with its status icon and count, then a thin proportion bar of the counts.
**Layout** Master–detail, draggable split. No `?result=` → the first shown result is selected; an unknown one → "This result is not part of this run."
**Rows** One per test in the run's frozen list. A test with no result (the run was stopped before it, D55) is **Not run** with the note "The run was stopped before this test"; it is selectable and can be re-run; its detail says there is no evidence (Re-run · Edit test only).

### Left: results list
- Toolbar (D80, D87): **Search** (with icon) on its own line; then the **Reason** filter pill "Reason: All ▾" · **Mode** as a segmented control (All · AI · Script · Data rows) · Worth a look toggle pill [PROPOSAL] · Clear filters on the next. Reason (BR-LIST-03): failed reasons when Failed is selected, couldn't-complete reasons when Couldn't complete is selected, and both under the headings "Failed" and "Couldn't complete" when All is selected; each option shows how many results it would show given the other filters ("Product bug (2)"); the pill turns accent while a reason is chosen, like the Worth a look toggle; for Passed and Not run it stays in place, disabled, reading "Reason: None for Passed" / "None for Not run". The pill fits its longest option; in a narrow pane the value is cut off with an ellipsis inside the pill.
- "Select all shown (n)" checkbox ("Most severe first" on the right). **Bulk bar** only when ≥1 selected, floating at the bottom centre of the window on one line (D80): "<n> selected" · Re-run · With model… (a menu of the configured models, opens upwards) · Copy bug reports · Known issue · Clear (×). Known issue for one result: result detail › More, or select it and use the bulk bar (D63). Deleted tests are left out of Re-run and Known issue; Copy bug reports leaves out results that did not fail (a message says how many) (D63).
- Rows (flat, sorted per BR-LIST-03; 13 px, D80): checkbox · status icon (✕ failed, ! couldn't complete (triangle), ✓ passed, ○ not run; with accessible label) · ID (monospace) · title · "Worth a look" label · "Known issue" label · second line muted "<reason> · <mode> · <suite>" ("Overridden" replaces the reason of an overridden result; a note is appended) · **cost** right-aligned. Multi-browser: browser marks with status icons (e.g. "✓ Chrome ✓ Firefox ✕ Safari") **only when the browsers disagree** (D85; when all agree the row icon says it); they follow the details when both fit, else take their own line, and are never cut off.

### Right: result detail

- Actions (D80), on the suite line above the title, primary last: Edit test · Override (not for Not run) · More (⋯) › Mark known issue / Update known issue (D63) · **Re-run** (primary; run dialog with this test, the run's environment and model). **Copy bug report** (**Failed** only, D63) sits in the failure summary card next to the recommendation; it moves to the action row only when there is no card. Each row also offers **Re-run** on hover or keyboard focus (D80). Chips also show Low confidence (BR-REASON-06), Script re-recorded (BR-RUN-07) and Known issue (· ticket; "marked by <user> · <date>").
- Worth-a-look banner with reason (if flagged) [PROPOSAL]. Override banner if overridden, showing the **latest** override ("Overridden to Passed by <user> · <date> · AI verdict: Failed · reason · proof"); earlier overrides are listed under **History** in the banner, newest first. Every override is kept; the newest applies (D62).
- Tabs: **Steps and evidence** · **Technical**.
- Steps and evidence:
  - **Browser** switcher (multi-browser results only, D86): one option per browser with its status icon (✓ Chrome | ✓ Firefox | ✕ Safari (WebKit)). It opens on the **lead browser** (the one the status comes from, BR-STATUS-03); `?browser=` selects another. The failure card, steps, screenshots, Visual compare and Copy bug report follow the selected browser. A browser whose status differs from the result shows "Passed in Firefox. The result is Failed because Safari (WebKit) failed."; a browser that did not run shows why ("Not run in Firefox: the AI run in Chrome failed, so there was no script to replay.", BR-RUN-03); a browser that ran with no stored steps shows "Not recorded".
  - **Failure summary card** (failed/couldn't complete): "Failed at step 2 of 3: <step text>" · **Expected** and **Found** side by side (D80) · reason explanation + recommended action (BR-REASON-04) with Copy bug report (Failed only).
  - "Show raw actions and locators" checkbox (remembered; D83).
  - Steps come from the test's own numbered steps; if the test has a single paragraph, the AI derives steps and labels them "AI-derived" (`Result.stepsSource`, D58).
  - Step list (3 levels): **intent step row** (status, "n. step text", "k actions · duration", screenshot thumbnail at the right) → expanded: Actions (plain language) · Check (expected → found) · AI reasoning (one line) · As recorded (raw action, locator, URL, full AI thought; only with "Show raw actions and locators"). **One screenshot per step** (D84): the thumbnail grows into a larger preview (up to 240 px, 16:9) when the step expands and shrinks back when it collapses; click either size → **6.2**, the one screenshot viewer (D88). **Visual mark** in the screenshot's top-right corner (D88): open changes show an amber mark (thumbnail: icon + number, e.g. "3"; preview: "3 areas changed"); a change marked Looks fine shows a green check (preview: "Looks fine"); no change and no comparison show no mark. The screenshot button's name carries the mark in words ("Open screenshot of step 2, 3 areas changed"). **Failed step expanded by default.**
  - Data rows breakdown (if data rows): Row · varied field/value · Expected · Result.
- Technical tab: Script & versions · AI thoughts · Usage (tokens, cost) · Knowledge used · Logs.
- Evidence the engine did not write (locator, URL, AI thought, tokens, knowledge used, logs) shows **"Not recorded"** (D58, CLAUDE.md rule 10).

## 6.2 Screenshot viewer / Visual compare (overlay)
The one viewer for a step's screenshot (D88), opened from a step's screenshot in 6.1 and from Suites › Visual check › Compare. It adapts to the step:
- **Compared step** (a script replay with an earlier replay, BR-VISUAL-02): as below, side by side.
- **Step not compared**: this run's screenshot full width (with the step's URL), and one line saying why, from `ResultStep.notCompared` (D88): "AI runs are not compared. Only script replays are compared with the previous replay." · "No earlier replay on <environment> · <browser> to compare with." · "Visual check is off for this test." · "Visual comparison was off for this project." · older results without a reason: "Not compared. Reason not recorded." No Mark as bug (there is no visual change to report); Ignore an area… stays (it applies to later comparisons); footer "Ignored areas are left out of later comparisons."

Header: "<ID> · Run #12 · Chrome 1920×1080" · "Step k of n · <step>" · Previous step / Next step / Close. Chip "<n> areas changed since the previous run". Two panels: **Previous run · Run #11** and **This run · Run #12** (changed areas outlined). (Third panel "Pinned reference" only if pinned — PARKED.) Footer note "A visual change is a flag, never a failure. Ignored areas are not compared." Actions: Mark as bug (→ 6.4, a report of the visual change: expected "as in Run #9", actual "n areas changed at step k") · Ignore an area… · **Looks fine** (dismisses the flag). Previous step / Next step move through every step with a screenshot, compared or not (D88).
**Looks fine** (D59): the change is kept and shows "Looks fine · <user> · <date>" with **Undo**; dismissed flags are not counted. Changed areas are outlined from `visual.changedRegions` when the engine returns them; otherwise the prototype outlines them at fixed placeholder positions (D64, open question 23).
**Drawing ignore areas** (D45): Ignore an area… draws the area on this step's screenshot. Suites › Visual check › **Add area** saves the area, then opens this view on the chosen step (of the latest comparison) to draw it; until drawn, an area shows "Not drawn yet" there, with **Draw** when that step has a screenshot. Drawing: drag on This run's screenshot, or focus the area and use arrow keys (move) / Shift + arrow keys (resize); name required; Save area. No new version (BR-VERSION-01).

## 6.4 Bug report (dialog, 720 px)
Note "Editable before copying. Paste into a ClickUp task." Card with editable fields: Title · Environment (env · platform · browser · viewport · run · date; the platform is the one whose URL has the test's start page host, else left out) · Steps to reproduce (numbered, plain language, up to the failing step) · Expected · Actual · Screenshots (thumbnails). Actions: Save screenshots (prototype: placeholder images) · **Copy report** (primary; copies formatted text). Bulk: one card per Failed result, each with Copy, and "Copy N reports"; other results are skipped with a message (D63).
